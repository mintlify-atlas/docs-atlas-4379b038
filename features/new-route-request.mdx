The **Nueva Ruta** modal is accessed from the Routes view via the **Nueva ruta** button. It registers a single delivery or pickup address as a route request, geocodes the destination in the browser, calculates the actual driving distance and time from the ScanMex distribution centre, and collects package cubicage data. The entire workflow is handled client-side by `nueva-ruta-integracion.js` and `paquetes-cubicaje.js`; the form submits to `/Rutas/GuardarRuta` once all required fields are filled.

## Fixed Origin

All routes calculated in this form start from the ScanMex headquarters:

```javascript
// wwwroot/js/nueva-ruta-integracion.js
const SCANMEX_ORIGIN = {
    direccion: "San Francisco 1107, Col del Valle Centro, Benito Juárez, 03100 Benito Juárez, CDMX",
    lat: 19.3850961,
    lng: -99.1770148
};
```

The origin marker is rendered as a dark-blue **O** circle on the map and cannot be changed by the user.

## Address Geocoding

When the user types or pastes an address into the **Dirección** field and moves focus away, `NuevaRutaMapa.geocodificarDireccion()` resolves the coordinates using a three-level fallback chain:

<Steps>
  <Step title="Google Places TextSearch">
    The primary strategy. Uses `google.maps.places.PlacesService.textSearch()` to find the address within Mexico. The address string is cleaned first (removes interior/exterior number markers, lot numbers, etc.) to improve match quality.
  </Step>
  <Step title="Nominatim OSM">
    If Google Places returns no result, a request is sent to `https://nominatim.openstreetmap.org/search` with `countrycodes=mx`. No API key required.
  </Step>
  <Step title="City/state fallback">
    If neither service resolves the full address, the last comma-separated segment is sent back to Google TextSearch as a city or state query.
  </Step>
  <Step title="CDMX random fallback">
    As a last resort, a coordinate within the CDMX bounding box is used so the map always renders something meaningful.
  </Step>
</Steps>

Once coordinates are obtained, `trazarRutaScanMexADestino()` calls `DirectionsService` to draw the real road path and populate the **Distancia** and **Duración** fields in the modal.

## Client Auto-Fill

Selecting a client from the SAP customer dropdown triggers a call to `GET /Rutas/GetClienteDetalle` which fills the address, phone, and contact fields automatically:

```javascript
// Triggered when the client dropdown value changes
GET /Rutas/GetClienteDetalle?bd=SMXCDM_PROD&rfc=ABC123456XYZ
```

The `bd` parameter selects the SAP company database (SMXCDM\_PROD, SMXMTY\_PROD, SMXGDL\_PROD, or SMXGOT\_PROD). See [Routes Module](/features/routes) for the full list of available databases.

## Package Cubicage Sub-Form

The lower section of the modal is designed to be powered by `paquetes-cubicaje.js` and allows the user to add one or more package items before submitting the request. Each item captures type, dimensions, and quantity; volume is computed entirely in the browser.

<Note>
  The `paquetes-cubicaje.js` script is currently commented out in the Rutas view (`@* <script src="~/js/paquetes-cubicaje.js" ...> *@`). The cubicage sub-form UI and the `PaqueteSolicitud` / `SolicitudRutaRequest` models are in place but the client-side module is not yet active. The `GuardarRutaDTO` payload sent by the active form does not include package data at this time.
</Note>

```javascript
// wwwroot/js/paquetes-cubicaje.js — volume calculation per item
const cubicajeCm3 = largo * ancho * alto * cantidad;
```

The total bultos count and total volume (shown in cm³ and m³) update live as items are added or removed. Pressing **Enter** in any dimension field triggers the same **Agregar** action as clicking the button.

## Request / Response

On submit the form POSTs to `/Rutas/GuardarRuta` with the full route payload. The shape of that payload matches the `GuardarRutaDTO` model (not `SolicitudRutaRequest`, which is used only by the simulation endpoint):

```json
// POST /Rutas/GuardarRuta  — request body
{
  "codigoRuta": "DEST-493021",
  "nombreRuta": "Entrega Distribuidora Norte",
  "fechaRuta": "2026-07-10",
  "idOperador": 4,
  "idVehiculo": 2,
  "origenDireccion": "San Francisco 1107, Col del Valle Centro, Benito Juárez, 03100 Benito Juárez, CDMX",
  "origenLat": 19.3850961,
  "origenLng": -99.1770148,
  "distanciaKm": 8.3,
  "tiempoEstimadoMin": 24,
  "destinos": [
    {
      "ordenSecuencia": 1,
      "cardCode": "C00123",
      "cardName": "Distribuidora Norte S.A.",
      "licTradNum": "DNO123456ABC",
      "address": "Av. Insurgentes Sur 1234, Col. del Valle, CDMX",
      "phone1": "+52 55 1234 5678",
      "cntctPrsn": "Lic. Pérez",
      "city": "Ciudad de México",
      "latitud": 19.3720,
      "longitud": -99.1680,
      "tipoDocumento": "Factura",
      "prioridad": "Media",
      "fechaCompromiso": "2026-07-10",
      "horarioEntrega": "09:00 - 11:00",
      "observaciones": "Presentarse con el Lic. Pérez en recepción."
    }
  ]
}
```

A successful save returns the route's assigned code:

```json
// 200 OK — response body
{
  "exito": true,
  "idRuta": 42,
  "codigoRuta": "DEST-493021",
  "mensaje": "Ruta guardada exitosamente."
}
```

After receiving a success response, the form clears all fields, removes the destination map marker, and triggers `NuevaRutaDashboard.cargarRutasDesdeBD()` to refresh the route cards in the background.

<Note>
  The legacy simulation endpoint `POST /api/solicitudes-ruta/simular` generates a folio (**REC-XXXXXX** for pickups, **ENT-XXXXXX** for deliveries) and echoes back the cubicage payload without persisting anything to the database. This endpoint is used only in demonstration flows. The production path through `/Rutas/GuardarRuta` writes to `LOG_Rutas` and `LOG_Rutas_Destinos`.
</Note>
