Scan4 — Pedidos Logística is the internal route-management system used by ScanMex to coordinate daily delivery operations. Built on ASP.NET Core 8 MVC, it brings together real-time Google Maps routing, live SAP Business One client data, and a role-based access model so that administrators, supervisors, and operators each see exactly the tools they need. From the moment a route request is created to the moment a driver closes out a delivery run, every step lives in one unified web application.

## Who uses Scan4?

Scan4 serves three groups inside ScanMex:

- **Administrators (U_Rol = '1')** — Full access to all modules including user management, vehicle registry, system configuration, and all route operations.
- **Supervisors (U_Rol = '2')** — Create and manage routes, assign operators and vehicles, reschedule deliveries, and view reports.
- **Operators (U_Rol = '3')** — Read-only view of their own assigned routes; cannot create, edit, or reassign.

## In-memory route repository and the SQL Server migration path

The map module's route data (`IRutaRepository`) is currently stored in a `ConcurrentDictionary` via `RutaRepositoryEnMemoria` — a Singleton service registered in `Program.cs`. This means created routes persist only for the lifetime of the running process and reset on restart. The design is intentional: because all controllers and front-end scripts consume the same `IRutaRepository` contract and the same JSON shape (`RutaLogisticaRequest`), swapping in a SQL Server–backed repository requires only a new class that implements `IRutaRepository` and a one-line change to the DI registration in `Program.cs`. No controller code, no JavaScript, and no API contracts need to change.

<Note>
The same migration-path principle applies to route-request folios (`IFolioGenerador`): the in-memory `FolioGeneradorEnMemoria` starts its counter at 400 and formats folios as `ENT-000401` / `REC-000401`. Replace with a database sequence when persisting solicitudes to SQL Server.
</Note>
